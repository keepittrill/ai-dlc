PART I / FOUNDATION

FIRST, THE THEORY

AI는 개발을 가속합니다.
SE는 방향과 책임을 지킵니다.

실무 기법부터 시작하면 도구 사용법만 남습니다. 먼저 무엇을 통제해야 하는지 공통 언어를 만듭니다.

01AI-DLC

AI와 사람이 전 과정에서 협업

기획·설계·구현·테스트·운영을 AI가 가속하고, 사람은 중요한 결정을 승인합니다.

02STANDARDS

빠뜨리지 않게 하는 공통 기준

12207·5338·29148·25010·SSDF·AI RMF가 생명주기, 요구, 품질, 보안, 위험을 채웁니다.

03V&V

만든 것과 필요한 것을 모두 확인

Verification은 명세대로 만들었는지, Validation은 실제로 쓸 만한지 묻습니다.

04OWNERSHIP

결정은 다시 사람에게 돌아온다

AI의 출력 속도가 빨라질수록 변경 영향·위험·출시 여부를 판단하는 책임이 커집니다.

THEORY 03표준 지도 — 빠뜨린 것을 찾아주는 체크리스트
PATH A

AI로 일반 SW를 개발

AI는 개발 도구이고 서비스 자체는 결정론적 SW입니다. 생명주기(12207)·요구사항(29148)·품질(25010)·테스트(29119)·보안(SSDF)이 기본 세트입니다.

12207 + 29148 + 25010 + 29119 + SSDF
PATH B

AI가 들어간 서비스를 개발

완성된 서비스가 LLM·추천·예측을 사용합니다. PATH A 위에 AI 생명주기(5338)·AI 위험(AI RMF)·거버넌스(42001)를 더합니다.

PATH A + 5338 + AI RMF + 42001
THEORY 04V&V — 만든 것과 필요한 것을 모두 확인
V1 · VERIFICATION

명세대로 만들었는가

레시피대로 요리했는지 확인합니다. 승인된 요구사항이 코드·설정·테스트에 빠짐없이 반영됐는지 검사합니다.

V2 · VALIDATION

필요한 것을 만들었는가

손님이 맛있다고 하는지 확인합니다. 실제 사용자와 현장에서 정말 가치를 내는지 검사합니다.

E · EVIDENCE

둘 다 증거로 판정한다

“AI가 잘 되던데요”는 주장입니다. 테스트 결과·로그·승인 기록 같은 재현 가능한 증거가 통과를 결정합니다.
