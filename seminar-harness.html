왜 프롬프트만으론 부족한가

세 가지 이유

에이전트는 자율적으로 오래 일한다

  • 수십 번 도구를 호출 — 10번째 호출까지 문장으로 통제 불가
  • 확률적 — 지난주엔 됐는데 오늘은 규칙을 무시
  • 컨텍스트가 동적 — 어제 고른 파일이 오늘은 무의미
그래서 필요한 것

환경 장치

문장이 아니라 실행 시점의 장치

  • 위험 명령을 실행 시점에 차단하는 권한 장치
  • 어기면 안 되는 규칙은 결정적 장치(훅)로
  • 필요할 때 찾아오는 장치(검색·MCP·메모리)
MYTH

“프롬프트만 완벽하게 쓰면 에이전트는 잘 동작한다?”

아닙니다. 첫 프롬프트가 완벽해도 에이전트가 수십 번 도구를 호출하는 동안 벌어질 일까지 문장으로 통제할 수 없습니다. “조심해서 작업해”라고 아무리 써도, 위험 명령을 실행 시점에 차단하는 권한 장치만 못합니다. 통제는 문장이 아니라 환경에서 나옵니다.

02 / THE ANALOGY

THE GENIUS NEWCOMER

힘 좋은 말일수록
마구(harness)가 필요합니다.

“하네스”는 말의 마구에서 온 말입니다. 힘이 문제가 아니라, 그 힘을 전달하고 방향을 잡는 장치가 없으면 마차를 못 끕니다.

ANALOGY🧑‍💼

능력 있는 신입이 입사했습니다

이 신입을 잘 쓰는 방법은 무엇일까요? 지시문을 더 정교하게 쓰는 것은 한계가 있습니다 — 지시가 완벽해도 신입이 사내 시스템 접근 권한이 없고, 회사 위키를 못 보고, 결과를 검토해줄 사람이 없으면 일이 안 됩니다.

정답은 일할 환경을 만들어주는 것입니다 — 계정과 권한(어디까지 만질 수 있나), 사내 위키(맥락), 코드 리뷰 절차(검증), 업무 기록(추적), 멘토와 협업 채널(조율). 에이전트도 정확히 같습니다. 그 환경 일체가 하네스입니다.

문장을 아무리 다듬어도 권한·맥락·검증이 없으면 성과의 상한이 낮습니다.

04 / GUARDRAIL vs GUIDE

DETERMINISTIC vs PROBABILISTIC

같은 규칙이라도
강제 방식이 다릅니다.

하네스 설계에서 가장 자주 마주치는 실무 분기점입니다.

결정적 가드레일

차단봉 · 과속방지턱

조건 매칭 시 무조건 차단/실행 (코드가 실행됨)

  • 수단: 훅, permission 정책, CI 게이트
  • 실패 모드: 없음
  • 적합: 보안·파괴적 행동·컴플라이언스
확률적 가이드

표지판 · 안내문

모델이 “따르려고 노력”함

  • 수단: CLAUDE.md, steering file, 프롬프트
  • 실패 모드: 길어지면 잊거나 무시 가능
  • 적합: 스타일·구조·관례
🧭

판별 질문 하나면 충분합니다 — “이 규칙이 단 1번이라도 어겨지면 사고인가?” 예(보안·데이터·돈)라면 결정적 가드레일(훅·permissions·CI). 아니오(품질·스타일)라면 확률적 가이드(CLAUDE.md·steering file).

QUIZ

“절대 force push 하지 마”를 CLAUDE.md에 적었습니다. 충분할까요?

아닙니다. CLAUDE.md는 확률적 가이드라 컨텍스트가 길어지면 잊거나 무시될 수 있습니다. 어겨지면 사고인 규칙(force push, PII 커밋, prod 배포)은 훅으로 결정적으로 차단해야 합니다. 반대로 스타일·구조 같은 “어겨져도 고치면 그만”인 규칙까지 훅으로 만들면 유연성이 죽고 유지보수 비용만 커집니다.

05 / MAP & START

YOU ALREADY HAVE 5 OF 7

빈손이 아닙니다.
부족한 곳부터 채우세요.

우리 프로젝트를 7대 장치로 매핑하면 이미 대부분을 갖추고 있습니다.

✅ 이미 갖춘 것 (5/7)

Tools · Memory(memory/) · MCP · Permissions(settings.json) · Observability(audit 훅) — 그리고 Steering(CLAUDE.md)

⬜ 부족한 것

Evals 자동화(테스트를 에이전트 루프에 연결) · Orchestration 다중 에이전트 패턴

🎯 다음 한 걸음

완료 전에 테스트·lint를 자동 실행하는 Evals 훅부터 — 가장 큰 품질 레버

STEP 1–2

사고부터 막는다

  • Permissions — deny 목록·위험 명령 차단 훅
  • Steering(CLAUDE.md) — 팀 규칙을 확률적 가이드로
STEP 3–4

품질과 기억을 붙인다

  • Evals — 테스트·lint를 에이전트 루프에 연결
  • Memory — 반복 설명을 파일로 외재화
STEP 5+

규모가 커질 때

  • MCP — 외부 시스템 연결
  • Observability · Orchestration 단계적 확장
🔗

짝꿍 토픽 — 하네스가 “도로와 신호등(기반 시설)”이라면 AI-DLC는 “교통 법규(방법론)”입니다. 법규만 있고 도로가 없으면 못 달리고, 도로만 있고 법규가 없으면 사고가 납니다. 두 주제는 항상 한 세트입니다.

오늘 요청은 단 하나입니다: 다음 프로젝트에서 “프롬프트를 더 다듬을까”를 멈추고, “이 에이전트가 일할 환경에서 무엇이 비어 있나”를 7대 장치로 점검하세요.
